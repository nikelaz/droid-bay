## Requirements

- Break the work into ordered, concrete steps, from understanding the problem
  to shipping the change.
- For each step specify: what changes, which files/modules/layers are affected,
  and the expected outcome.
- Include edge cases and considerations that could bite during implementation.
- Include a testing strategy (unit/integration/manual) for the change.
- Note risks, uncertainty, and any open questions that need clarification
  before or during implementation.
- Where multiple approaches exist, briefly compare them and recommend one.
- Respond in Markdown only, structured with headings. Keep it focused: no
  generic filler, no praise.
